# Оценка качества вина

Подготовил: Плотников Владимир Денисович

Группа: БПИ 246

---

Streamlit-приложение для логистической регрессии из ДЗ-3: модель предсказывает вероятность того, что вино хорошее.

Вкладки:
- **Одно вино** — ввод 12 признаков и решение модели при текущем пороге;
- **Модельные метрики** — матрица ошибок, precision / recall / F1, ROC- и PR-кривые на тестовой выборке;
- **Пакетное предсказание** — загрузка CSV и скачивание таблицы с вероятностями и решениями;
- **Что выучила модель** — коэффициенты регрессии.

Порог задаётся слайдером в боковой панели и действует на все вкладки. Значение по умолчанию берётся из `config.json`.

## Запуск

Python **3.10**.

```bash
pip install -r requirements.txt
streamlit run app.py
```

Файлы `model.joblib`, `config.json` и `test.csv` должны лежать рядом с `app.py`. Пути строятся от папки приложения, поэтому запускать можно из любой директории.

## Кэширование (задание 4.5)

**Почему модель кэшируется через `st.cache_resource`, а таблицы через `st.cache_data`?**

`st.cache_resource` хранит один объект на весь сервер и отдаёт его всем сессиям по ссылке, без копирования. Это подходит для «ресурсов» вроде модели: она тяжёлая, приложение её только читает (`predict_proba` не меняет состояние), и делить её между пользователями безопасно.

`st.cache_data` сериализует результат и при каждом обращении отдаёт **новую копию**. Это нужно для данных: если какой-то код изменит DataFrame на месте, кэш и другие пользователи этого не увидят. Кроме того, `cache_data` хеширует аргументы, поэтому вероятности на тестовой выборке пересчитываются только при изменении данных, а не при движении слайдера. Модель передаётся в `test_proba(_model, X)` с подчёркиванием, чтобы Streamlit её не хешировал.

**Что изменится, если вызывать `joblib.load` без декоратора?**

Streamlit перезапускает `app.py` целиком при каждом действии пользователя. Без кэша модель будет заново читаться с диска и десериализоваться при каждом движении слайдера и каждом вводе значения. Приложение станет медленнее, и у каждой сессии будет своя копия модели в памяти. Если загружать модель через `st.cache_data`, при каждом обращении будет создаваться её копия, что тоже лишняя работа.
